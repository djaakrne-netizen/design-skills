# Live Code-Component References

Use these sources when the user needs both visual inspiration and implementation-ready behavior. Re-check the live source because component inventory, pricing, dependencies, and license terms can change.

## Select Codes

- Site: [Select Codes](https://select.codes/)
- Components: [Component catalog](https://select.codes/components)
- Pricing and access: [Max](https://select.codes/pricing)
- Best fit: React and Next.js interfaces using TypeScript, Tailwind CSS, Motion, or shadcn-compatible installation patterns.
- Use for: purposeful motion, tabs, cards, interactive sections, page transitions, polished micro-interactions, and finished-page composition references.

### Workflow

1. Confirm the project's framework, styling system, React version, and existing motion library.
2. Open the exact component page and inspect the live preview across available states and screen sizes.
3. Review the source, per-component dependencies, AI prompt, and installation instructions.
4. Prefer adapting the component to existing project tokens and primitives. Avoid introducing a second styling or animation system for one effect.
5. If the stack is incompatible, use the component only as a behavior and timing reference and reimplement it in the project's conventions.
6. Verify keyboard operation, focus visibility, contrast, touch targets, content expansion, mobile layout, performance, and `prefers-reduced-motion` behavior.

### Guardrails

- Treat free-versus-paid availability, price, inventory counts, and license terms as live facts and verify them at the time of use.
- Follow the site's license for personal, commercial, and client work. Do not redistribute or resell the component library itself.
- Do not copy paid source without valid access.
- Do not run `npx shadcn add` or install dependencies until compatibility and scope have been checked.
- Do not treat an AI prompt as authoritative implementation code; inspect the produced code and test it in the repository.
